# v2.6.0 harness control: the move reproduces every committed cell

[← Benchmark index](../benchmarks.md) · [Comparison harness](../comparison-harness.md) · [ADR-0027](../adr/0027-the-comparison-harness-is-protocol-agnostic.md)

v2.6.0 moved the comparison harness out of the `anthocnet` module into
`routing-bench`, and turned every arm-specific branch into a hook of the arm
([#767](https://github.com/danieljoppi/AntHocNet/issues/767),
[#768](https://github.com/danieljoppi/AntHocNet/issues/768)). ADR-0027 §4
accepts the move only if no published number moves. This page is the control
that checks it ([#769](https://github.com/danieljoppi/AntHocNet/issues/769)).

## Plan and rule

- **Plan:** `tools/bench/campaigns/v2.6.0-harness-control.yaml`, generation `pc769`.
  - It re-runs one cheap block (seeds 1–2) of every MANET-family cell committed in the v2.4.0 and v2.5.0 generations.
  - Every run goes through `routing-compare`, at the branch that moved the harness.
  - Each cell keeps its committed plan's own inputs and protocol list. Lists are never merged, because the identity-matched `##COMMON##` set depends on which arms share an invocation.
- **Rule:** every `##RUN##`, `##ROUTE##` and `##COMMON##` row for seeds 1–2 must equal the committed one. The check is `tools/bench/harness_control.py`.
  - The runs are deterministic (#129) and seed-pinned (#352), so any difference would be a defect in the move, not noise.

**The one red run.** `grid-rwp-nakagami` went red in GitHub Actions. Its
`scenario_check results` step FAILs on the known oracle-adjacency approximation
on a fading channel: the oracle's identity-matched hops are 1.189 against dsdv's
1.033 on seed 2. The committed `grid-rwp-nakagami-v240.txt` carries the same
FAIL with the same numbers, so the control reproduces it like every other row.
