# The v2.3.0 campaign — plan

**Status: pre-registered, not yet run.** This page fixes the arms, the cells
and the decision rule before the first dispatch, as the
[v2.2.0 campaign](v2.2.0-campaign.md) did. The plan file is
[`tools/bench/campaigns/v2.3.0.yaml`](https://github.com/danieljoppi/AntHocNet/blob/main/tools/bench/campaigns/v2.3.0.yaml),
and the jobs are dispatched and collected with

(#662).

## What this campaign decides

v2.3.0 adds regime-gated mechanisms. Each ships default off and is
byte-identical when off (the ADR-0020 check, run on each mechanism's PR). Each
targets a gap a published page measured:

| arm | mechanism | issue | target regime | the gap it targets |
|---|---|---|---|---|
| `ll` | link-lifetime prediction: discount a next hop by its predicted remaining lifetime (`EnableLinkLifetime`, range per cell) | [#574](https://github.com/danieljoppi/AntHocNet/issues/574) | VANET | 42.1 % vs the oracle's 81.7 % on VANET main ([vanet.md](scenarios/vanet.md)) |
| `quiet` | quiet mode: back proactive ants off on a stable route (`EnableQuietMode`) | [#571](https://github.com/danieljoppi/AntHocNet/issues/571) | static mesh | NRL 4.51 vs OLSR's 1.78 ([static-mesh.md](static-mesh.md)) |
| `evap` | adaptive evaporation: each destination's decay follows its route churn (`EnableAdaptiveEvaporation`) | [#572](https://github.com/danieljoppi/AntHocNet/issues/572) | LEO shells, VANET | walker16's 2.07 hop changes per flow-minute vs the oracles' ~1.0 ([leo-walker.md](satellite/leo-walker.md)) |
| `energy` | the energy-aware metric (`LinkMetric=energy`) | [#145](https://github.com/danieljoppi/AntHocNet/issues/145) | battery-limited fields | not yet a harness metric; see below |
| `timing` | the propagation timing profile: `T_hop` = mean ISL propagation (`--timingProfile=propagation`) | [#205](https://github.com/danieljoppi/AntHocNet/issues/205) | satellite | 15.5 pp under the delay oracle on Starlink S1, 7.0 pp on walker16 |
| `p2phello` | a hello every 5th tick on point-to-point ISLs (`P2pHelloEvery=5`) | [#204](https://github.com/danieljoppi/AntHocNet/issues/204) | static ISL grid | hellos cost NRL and discover nothing on a fixed link (v2.2.0's `hello500` data) |

## The cells

The 18 cells of the v2.2.0 corpus, with their recorded dispatch inputs:
- the MANET grid (6);
- the static mesh;
- FANET main and sparse;
- VANET main (five 4-seed blocks) and sparse (two 10-seed blocks);
- the four ISL-grid cells;
- the three LEO shells.

Every cell runs 20 seeds. The `-opt` image runs everything except leo-walker,
which runs on ns-3.48.

## Arms and where they run

| arm | protocols | cells | why |
|---|---|---|---|
| `control` | every protocol the cell publishes | all 18 | the shipped defaults at the campaign commit; also v2.3.0's corpus if no default moves |
| `ll`, `quiet`, `evap`, `energy` | `anthocnet` | all 18 | ADR-0019: a mechanism is measured in every family, not only its target |
| `timing` | `anthocnet` | 4 ISL-grid + 3 LEO | the profile is a satellite-harness option; on Wi-Fi cells T_hop is the thesis's 3 ms |
| `p2phello` | `anthocnet` | 4 ISL-grid | safe only where a failed ISL takes its interface down. leo-walker's failure overlay drops packets on a link that stays up, which a throttled hello would hide (configuration.md, `P2pHelloEvery`) |

Notes on what each arm means per cell, stated before any number exists:
- **`ll` on the satellite cells:** point-to-point ISLs have no radio range. The
  plan uses 5000 km, about the longest ISL, as a geometric proxy. On the static
  ISL grid nothing moves, so no link is predicted to end, and the arm should
  read as a no-op there. On the LEO shells it discounts links whose endpoints
  are separating. The pages say so next to any satellite `ll` number.
- **`energy`:** the Wi-Fi harness gives each node 5000 J, sized so that no node
  dies in 900 s (`anthocnet-compare.cc`, `kDefaultEnergyJ`). Residual energy
  then stays above ~85 %, so the metric prices hops at about 1.0–1.2, and it
  behaves close to hop count. The arm measures what the metric costs when
  batteries are not the binding constraint. A battery-limited cell (lower
  `--energyJ`, first-node-death as the outcome) is follow-up work, not this
  campaign. On the satellite harnesses no energy probe is set, so the metric
  is plain hop count, as `sinr` was there in v2.2.0.
- **`quiet` on mobile cells:** routes change, so the back-off should rarely
  engage, and the arm should read as noise. A loss there is the finding to
  look for.

## Pre-registered decision rule

The rule is [v2.2.0's](v2.2.0-campaign.md#pre-registered-decision-rule),
unchanged:
- every comparison is paired per seed against `control`, on the same 20 seeds,
  with `campaign.py verdicts` (`bench_parse.py --ab`);
- **a default moves only if** no cell is `PAIRED-WORSE` on PDR, no cell is
  `PAIRED-WORSE` on delay99 by more than 10 % while PDR is `NOISE`, and at
  least one family is `PAIRED-IMPROVED`;
- **otherwise the mechanism ships selectable and off,** and its per-family
  deltas go into the mechanism × regime table in
  [network-regimes.md](../network-regimes.md).

v2.3.0's own exit criterion, from the [roadmap](../roadmap.md), adds one line:
**each mechanism must show a paired improvement in its target family.** A
mechanism that does not is recorded on its issue as not earning its place,
and the issue stays open with the data.

For `quiet` and `p2phello`, whose target is overhead, "improvement" is NRL
`PAIRED-IMPROVED` with PDR not `PAIRED-WORSE` in the target cells.

**Attribution:** in one cell per family, `bench_parse.py --control` compares
the control's baseline rows against v2.2.0's corpus. Every baseline row must
be identical, except stock AODV on the satellite cells, which may read
ORDER-ONLY (#675). Anything else means the harness moved, and that family's
deltas are not attributable until it is explained.

**If two or more defaults move,** a `combined` arm runs in all 18 cells with
every protocol, and that generation is what the pages publish.

## Phase order

1. **Code, no runs.** Merge each mechanism with its core tests and the
   byte-identity evidence. Merge this plan. Preflight every cell (0 FAIL since
   #663).
2. **Screen (done before this plan):** `ll` on VANET main and sparse and the
   two Nakagami grid cells, paired against a same-commit control. Its result
   is recorded on #574. It does not decide anything; it only checked that the
   mechanism acts.
3. **Campaign:** all 139 jobs at `main`, at most 12 runs active (#662). Each
   arm's verdict goes on its issue when its last cell lands (ADR-0013).
4. **Decide and restate:** apply the rule, fill the mechanism × regime table,
   restate the family pages if a default moved, and update the roadmap row.

## What would make this plan wrong

- **The control disagrees with the v2.2.0 corpus** on a row the #675 control
  calls a FAIL. Stop: the harness moved.
- **An arm's attribute does not reach the run** (its `##CONFIG## attr` line
  shows the default). The cell is void; re-dispatch it.
- **`ll` is identical to `control` on VANET.** The hellos then carry no
  kinematics, or the range is wrong: diagnose before spending more seeds.
