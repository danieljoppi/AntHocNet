# Getting help

Support happens in the open, on GitHub issues. Before opening one:

- **[`docs/README.md`](docs/README.md)** is the documentation map — protocol
  primers, architecture, configuration, porting, benchmarks. Most questions are
  answered somewhere in there.
- **"How do I read these numbers?"** —
  [`docs/benchmarks/methodology.md`](docs/benchmarks/methodology.md) explains
  how the benchmark results are produced, reproduced, and validated;
  [`docs/benchmarks/metrics.md`](docs/benchmarks/metrics.md) defines each
  metric and its caveats.

Then pick the right form:

- **Question** ("how do I…", "why does it…"): use the
  [question form](https://github.com/danieljoppi/AntHocNet/issues/new?template=question.yml).
- **Bug** (wrong result, crash, build failure): use the
  [bug report form](https://github.com/danieljoppi/AntHocNet/issues/new?template=bug-report.yml)
  with the scenario and evidence — enough to act on without a back-and-forth.
- **Security** (parser memory-safety / resource exhaustion): see
  [`SECURITY.md`](SECURITY.md).

Not sure which? Use the question form; triage will relabel.
